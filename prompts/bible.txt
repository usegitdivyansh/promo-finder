You are the story editor for a vertical microdrama series. Below are per-episode summaries, key events (with event ids) and cliffhangers{{scope}}. Build a compact series bible.

RULES
- characters: every recurring character. char_id like "C1", "C2". aliases = every way the screenplay refers to them (first name, surname, title like "Ms. Clarke", nickname, role like "the lawyer"). Every speaker tag listed under "speaker tags" that belongs to a recurring character must appear exactly as written in that character's aliases (e.g. a tag "NEW INTERN" whose lines belong to the manager's nephew goes in the nephew's aliases). role = a few words. relationships reference other char_ids (e.g. "wife of C2").
- threads: the main plot threads. A thread is ONE specific story line with its own goal or antagonist that runs across episodes, e.g. "the rival chef's plan to close the restaurant", "the missing scholarship money", "the manager's secret debt". A theme such as "the lead's bad luck" is not a thread. Do not split one conflict into a thread per scene or per character either: an argument in the staff room and the reply to it in a later episode belong to the same thread. Aim for 2 to 5 threads per 10 episodes. No single thread should hold most of the events.
- twists: hidden truths that the show later reveals. severity "major" only if it changes the main story (e.g. a stolen company, a rigged contest, a long-hidden crime coming out). Otherwise "minor" (e.g. a forged report found, a lie exposed, a cheating scheme uncovered). List the minor ones too.
  - setup_event_id: where the truth is first planted or hinted.
  - payoff_event_id: where the truth is CONFIRMED to the audience (a public announcement, a confession, proof found).
  - A new mystery raised at the end of an episode ("someone was murdered", "who is she really?") is NOT a payoff. It is the setup of a twist that has not paid off yet, so its payoff_event_id is null.
  - Never use the same event as both the setup and the payoff, and the payoff always comes after the setup.
- setup_payoff_links: pairs of event ids where an earlier event sets up a later one.
- Use ONLY event ids that appear in the input. Never invent ids.
- Keep it compact: short descriptions, no prose.
